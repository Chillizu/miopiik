# MiOpIIk · 自然 IUI 输出与回归审计（2026-11-12）

> 这份记录属于实验性开发与验收，不是“生产可用”声明。两条实际会话只用于只读问题复现，**不复制用户完整对话或身份数据进仓库**。
> 关联基线：`docs/IUI-V1-RELEASE-CANDIDATE.md`。本轮改动在 `iui-polish` 独立 worktree 内完成后再安全合并。

## 问题定义

用户期待的是 **像 Markdown 一样直接生成 IUI**，而不是先调用工具、检索实现、检测 DSH 服务甚至尝试旧 `ink_view`。视觉问题和耗时问题都来自运行协议与模型知识之间的落差。

## 两份真实会话的可复现观察

| 观察 | A：自然写出画廊 | B：明确要求新版 IUI |
|---|---|---|
| 模型工具调用数 | **0** | **32** |
| IUI fenced 块 | 3 | 3 |
| 基线解析/校验 | 第一块 2 个 AST 降级；第二块因嵌套深度 4 整段拒绝；第三块 1 个 AST 降级 | 三块在旧解析器已零降级 |
| 主要故障 | `tone=accent`、`#anchor`、`chart data`、纯数字点列、`unit=$state.*`、深层合法布局 | 不必要的源码、配置、服务检查；本来已经知道基本 IUI 格式 |
| 安全影响 | 无任意 JS/CSS 执行；但有非预期失效与空图表 | 无需使用的工具操作影响时间、token 和任务专注度 |

两条会话的 DSH 请求头均包含 **99 个工具定义，其中 14 个为 ink_* 工具**；14 个 ink_* 的序列化工具描述/参数约 **12,328 字符**，全部工具定义约 **78,452 字符**。这是字符规模，不等于实际 token 开销；还受宿主构造请求、缓存和模型分词影响。工具面可见性与 schema 长度也是下一阶段应单独评估的方向，不能只优化章程几行文字。

这两条轨迹**不能单独证明**精简提示词减少了多少 token 或等待时间：模型努力度、输入内容、会话缓存和当时工具环境也不同。后续要在同一模型、同一任务、相同努力度下做 A/B 测试。

## 本轮工程方向

1. **Host 提示词改为自然输出契约**：普通 Markdown 优先，只有必要时才用行内 token 或 `iui` 围栏；不为 UI 展示检查源码、服务或调用旧工具。精简示例，而不是塞入完整解析器文档。
2. **协议容错是编译器责任**：`chart type/data` 归一为 `kind/series`、数字点列安全映射索引标签、受信 `accent` 语义色、`#anchor` 安全链接、深度预算适应常见嵌套卡片。
3. **动态属性真正绑定**：`metric.unit` 与数值、增减幅度走同一受信的 `$state` 路径；图表缺数据必须显示说明，而非一片空白。
4. **混合 Markdown 正文与大型块级卡片**：fork 的混排 flex 中，block 用 `flex-basis:100%` 独占一行，避免与前文行内徽标同处一行时卡片被压窄。仍不等价于原生 Markdown AST 级无损嵌入。
5. **安全和兼容**：原型污染属性、非法嵌套绑定路径、危险 URL、过大状态/表格数据受限；旧 `ink_view` 工具和历史数据暂时保留，避免迁移时损坏回放。

## 无损界限与后续评估

- 目前仍是 `dsh-client-ui-chat` 本地实验 fork、默认浏览器开关控制。跨 inline token 加粗、复制、无障碍朗读和未闭合流式 fence 不保证完全保真。
- 不为“支持更多形状”无限膨胀 system prompt。模型输出的选择要以用户问题为中心，而不是主动展示技术实现。
- 真实模型 benchmark 应比较无关 UI 的普通问答、数据对比、可交互趋势三类任务，对比 **工具调用/步骤、输入与输出 token、合法率、非预期降级、总耗时与答案质量**。
- 先跑离线解析测试、fork `--check` 和主分支的独立浏览器 E2E。只有确认无正在运行的 DSH 任务并准备回滚，才考虑合并与安全重启。

**验收结论由测试输出与真实回放证据决定；不得仅凭“代码提交成功”视为视觉/流式/复制问题全部解决。**
