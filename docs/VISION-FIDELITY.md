# 愿景保真度审计

> 对照对象：最初提出的架构构想（MiOpIIk = M/O/T 三层 + 鱼骨上下文树 + 前后台分离）。
> 判据：实际运行时，用户体验是否符合设计目标。
> 审计时间：2026-11-04。状态：`[OK]` 成立 ｜ `[PARTIAL]` 部分成立 ｜ `[FAIL]` 未成立。

## 一句话愿景

> **持续对话与异步行动相互独立又自然协作；任务从对话中产生，执行在后台推进，结果经整理后重新融入对话，用户的思路始终是交互中心。**

## 逐条对照

### 1. 「M 是持续与用户交流的主体，接到模糊指令时不直接进入长程执行」

- 现状：`[OK]`
- 证据：`host/prompt.js` 章程规定派发前自检（能够复述目标并说明完成标准）；`host/contract.js` 校验六要素，缺一即拒绝派发并返回缺失字段清单。
- 说明：M 仍持有 DSH 默认的 bash 等基础工具，窄工具面在 Mind 侧通过章程与子 agent 工具隔离配合约束。

### 2. 「M 始终关注用户，长程任务交给后台」

- 现状：`[PARTIAL]`
- 证据：`ink_dispatch` 通过 `ctx.subagents` 以 `delivery: 'caller'` 启动子会话，结果返回给 Ink；O 的会话与 M 的会话完全分离（实测 J-1…J-5 五个 Operator 均在各自独立子会话中运行）。
- 缺口：M 自身的基础执行工具未在宿主层硬性剥离，主要依靠章程与派发门槛约束。

### 3. 「O 调度、T 执行、可递归」

- 现状：`[OK]`（合并后）
- 证据：`host/operator.js` 使用 `ctx.subagents` 派发，子 agent 可按需继续派发子任务；O/T 合并为统一的 Operator 层（见 SPEC §7）。

### 4. 「鱼骨式上下文树：主干是对话，分支从对话节点长出、可递归、适时汇回主干」

- 现状：`[PARTIAL]`
- 已落地（2026-11-04 第二轮）：`branches.jsonl`、`ink_branch`（`open` / `summary` / `merge` / `abandon`）及 `ink_dispatch` 的 `branch` 绑定；分支记录 `forkedAtTurn` 与事件序号；L3 展示活跃鱼骨分支摘要；汇回主干时生成带分支指针的收件箱预览；后台面板列出鱼骨分支。
- 实测（同一会话内）：`B-1` 从第 24 轮分叉，L3 出现对应分支行，merge 产出 `D-9`（进入收件箱 T1），面板通过 projection 增量更新 `B-2`。
- 上下文切片（2026-11-04 第三轮，已实测）：分支携带 `premise`、主干原文 `quotes` 与依赖 `facts`；派发时切片直接注入 Operator 的派发提示；`ink_branch get` 供 Mind 读取分支切片。
- **实测证据**：向分支 B-2 派发「仅凭派发提示复述前提与依赖事实」的任务，Operator 在 0 次工具调用、未读任何文件的情况下，准确复述了前提与 `F-2`，验证了分支切片的独立上下文传递。
- 同期修复：补齐分支任务结果的分支指针（避免落入 T3）；编译失败时增加一次重试，并将失败原因写入 `why` 字段供审计。
- 两阶段折叠：影子提案 → Mind 持有旧上下文验收 → 通过后记账并调度宿主 compaction（若宿主未暴露 compaction 服务，则仅记录提案，详见 SPEC §11）。
- 仍缺：分支递归（分支下再开子分支）；跨分支可见性；切片依赖需由 Mind 显式追加。

### 5b. 「探索态免门槛：M 可先在草稿区尝试，失败不打扰用户」

- 现状：`[OK]`
- 证据：`ink_dispatch` 的 `draft: true` 仅要求一句目标；产出进入草稿区（7 天未触碰自动过期），不进入收件箱；关联开环自动结算为 `draft:settled`。实测探索任务完成后落在草稿 P-2，收件箱零新增。

### 5. 「用户提想法时，M 一边回复一边判断是否值得执行；区分探索/成形/行动」

- 现状：`[OK]`
- 证据：不设独立意图分类器，改用可验收性自检（能否一句话复述目标并说明完成标准）；正式派发校验六要素，探索态走 `ink_draft` 与 `draft: true` 派发。

### 6. 「M 前台与后台分离：共享必要状态，不共享推理细节，两条时间线并行」

- 现状：`[PARTIAL]`
- 证据：Ink 作为独立于前台对话的常驻层（事件驱动 + 定时老化 + 守夜），与 M 的时间线并行推进。
- 说明：系统不设两个并发对话 M 实例；判断权留在 Mind，Ink 负责连续上下文记账与异步编译（符合 SPEC 对双 M 方案的取舍）。

### 7. 「O 的结果不原样插入主对话」

- 现状：`[OK]`
- 修复记录：编译降级预览的 claim 改为仅截取契约目标（`clip(goal, 26)`），Operator 报告全文存入 `detail`，需调用 `ink_inbox open` 才展开；`hold` 状态的 claim 统一为固定中文说明，原问题存入 `detail`。

### 8. 「渐进式任务可见性：M 只掌握目标、关键进度、结论，需要时再深入」

- 现状：`[OK]`
- 证据：L3 仅注入单行预览（claim + 关联开环/分支 + 问题）；详情通过 `ink_inbox open` 按需读取；Operator 的中间步骤不进入 M 的上下文。

### 9. 「自然打断与注意力恢复：无关信息暂存、相关信息自然融入、重要发现影响方案、切话题后能恢复」

- 现状：`[PARTIAL]`
- 已落地：收件箱分层（T0–T3）、字符预算控制、同一开环合并未读预览；epoch 推进使旧预览降级；开环 2 天休眠 / 7 天折叠；L3 提供对话节奏信号（最近三条长度、确认型回复数、停顿分钟数、活跃开环数），供 Mind 判断展示时机。
- 说话节点与回溯：每条发言分配稳定 id（`U-<seq>`），编译时关联早期相关发言，出现矛盾时指认具体 `U-<seq>`；检测到道别信号时提醒撰写收工简报。
- 缺口：话题切换仍需 Mind 显式调用 `ink_epoch advance`。

### 9b. 「跨天：次日开工能够续接」

- 现状：`[OK]`
- 证据：`test/crossday.test.js` 基于真实账本与重启流程验证：L3 自动加载交接简报、关联具体开环与闭合条件、控制在单屏字数上限内，且恢复过程无额外写盘副作用。

### 9c. 「用户词表五个面全部落地」

- 现状：`[OK]`
- 证据：后台面板五个部分均有真实数据绑定——悬着的事（可关闭/丢弃）、我们一起定的（可标废）、后台在跑（任务与分支）、草稿（P-1/P-2）、今天的信（五段交接简报）。实测截图见 `docs/screenshots/todays-letter.png`。

### 9e. 「细节归档与按需检索」

- 现状：`[OK]`
- 证据：详情按内容 hash 落盘去重，note 内保留 120 字预览与 hash 指针；`ink_recall` 支持按关键词、实体、开环、分支、天数检索并按 hash 读回全文。过期回收仅清理无引用条目，保留所有被引用证据。

### 9d. 「配置可视化」

- 现状：`[OK]`
- 证据：设置页列出全部可调项（账本目录、开环上限、老化天数、简报字数、预览字符预算、Operator 超时与无进展阈值、编译模型等），默认值统一读取自 `host/config-defaults.js`。

### 10. 「用户不必关注任务调度、执行状态和技术细节」

- 现状：`[PARTIAL]`（产品界面 `[OK]`，对话习惯需持续约束）
- 产品界面：客户端后台状态收敛在专用面板中，不打断主聊天流。
- 对话约束：Mind 在回复用户时应直接交流结论与下一步，避免在对话中播报批次号、测试数量或提交哈希（已写入章程）。

### 11. 「用户思路始终是交互的中心」

- 现状：`[PARTIAL]`
- 已落地：收件箱预览以简短问句结尾，由 Mind 在话题间隙自然提起；提交门只要求「行 / 不行」判断。
- 缺口：用户临时岔开话题后的主线恢复仍依赖 Mind 对 L3 开环的把握。

## 结论

核心架构（对话与后台行动解耦、结果经编译回流、渐进可见、提交门二元确认、鱼骨分支切片与跨天简报）均已实现并通过实机验证。后续重点在于保持 Mind 对话风格的克制，以及按需扩展多级分支能力。
